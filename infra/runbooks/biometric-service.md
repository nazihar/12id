# Runbook: biometric-service (staging)

Phase 6 biometric gate ([`16-phase-6-biometric.md`](../../implement/16-phase-6-biometric.md)). An internal service that holds each tenant's biometric vendor configuration and the reference images of pending face checks, both encrypted. It decides liveness + face match through the vendor adapters. platform-api is its only caller.

## What runs where

| Piece | Where | Notes |
|---|---|---|
| `biometric-service` | `compose.biometric.yml`, networks `12id-agent` + `12id-biometric` | Not published on the host. Outbound HTTPS to AWS |
| `biometric` database | `agent-postgres` | Created and migrated by `biometric-provision`; backed up nightly with the agent databases |
| platform-api | joins `12id-biometric` | `BIOMETRIC_SERVICE_URL=http://biometric-service:3430`, `BIOMETRIC_SERVICE_TOKEN` |

## Secrets (`secrets/biometric.sops.env`)

| Key | What | How to create |
|---|---|---|
| `BIOMETRIC_MASTER_KEY` | 32 random bytes, base64. Wraps every tenant's data key | `openssl rand -base64 32`. **Losing it makes every stored provider config and pending reference image unreadable.** Back it up with the age key |
| `BIOMETRIC_INTERNAL_TOKEN` | platform-api → biometric-service | `openssl rand -hex 32`. The same value is read by the platform stack through `EXTRA_SECRETS="… biometric"` |
| `BIOMETRIC_AWS_ACCESS_KEY_ID` / `BIOMETRIC_AWS_SECRET_ACCESS_KEY` | 12id's own AWS principal. It only needs `sts:AssumeRole`; tenants' roles trust it | An IAM user in 12id's AWS account with only `sts:AssumeRole` on `arn:aws:iam::*:role/*`. Without it the `aws-rekognition` provider is not offered |

Create on the VM (never commit plaintext):

```sh
cd /opt/12id/12id
sops infra/staging/secrets/biometric.sops.env   # opens an editor; add the four keys
```

Then commit the encrypted file from the VM, or copy it back, before the next tree sync (trap 45).

## Deploy

```sh
EXTRA_SECRETS="agent" infra/scripts/deploy.sh biometric up -d --build
EXTRA_SECRETS="ledger mediator" infra/scripts/deploy.sh agent up -d          # phase6 image: hold points
EXTRA_SECRETS="agent mediator biometric console" infra/scripts/deploy.sh platform up -d
```

`console` stays in the platform line until the VM's `platform.sops.env` has `CONSOLE_TOKEN` again (see the Phase 4 note in `console.md`).

Check:

```sh
EXTRA_SECRETS="agent" infra/scripts/deploy.sh biometric ps
docker exec platform-platform-api-1 node -e 'fetch("http://biometric-service:3430/healthz").then(r=>r.text()).then(console.log)'
curl -s https://api.<domain>/readyz   # checks.biometric = true
```

## Tenant AWS setup (what the console's "AWS setup" panel tells tenants)

1. In the tenant's AWS account, create a role that 12id's principal may assume, with **Require external ID** set to the value the console shows (per tenant, generated by biometric-service).
   Trust policy:
   ```json
   {
     "Version": "2012-10-17",
     "Statement": [{
       "Effect": "Allow",
       "Principal": { "AWS": "<12id principal ARN>" },
       "Action": "sts:AssumeRole",
       "Condition": { "StringEquals": { "sts:ExternalId": "<external id from the console>" } }
     }]
   }
   ```
2. Inline permissions: `rekognition:CreateFaceLivenessSession`, `rekognition:GetFaceLivenessSessionResults`, `rekognition:StartFaceLivenessSession`, `rekognition:CompareFaces` on `*`.
3. Console → Biometrics → Configure provider (region + role ARN) → Test connection → switch on.

The device receives 15-minute credentials from the same role, narrowed by a session policy to `StartFaceLivenessSession`. No S3 output is configured, so AWS stores no images.

## Master key rotation

There is no online re-wrap tool yet. Rotation means: stop biometric-service, run a one-off script that unwraps every `tenant_keys.wrapped_key` with the old key and re-wraps it with the new one in one transaction, swap the key in sops, start the service. Only the data keys change; ciphertexts do not. Write that script before the first production key exists.

## Restore

See `backup-restore.md` (the `biometric` row). A restored database needs the same `BIOMETRIC_MASTER_KEY`. Pending checks in the dump have expired by the time anyone restores, and the service wipes their images on its first sweep.

## Troubleshooting

| Symptom | Cause |
|---|---|
| Console "Test connection" fails with `AccessDenied … sts:AssumeRole` | The tenant's trust policy names the wrong principal, or lacks the external id |
| Test passes but the phone shows an error at capture | The role lacks `StartFaceLivenessSession`, or the region differs from the tenant's config |
| `result_not_ready` repeatedly | The device has not finished streaming; the SDK retries for 15 s |
| Every check fails `no_face` | The reference image has no detectable face (too small, cropped, or a photo of a document page) |
| `provider_not_tested` on offers | The tenant changed its provider config; run the test again |
